# Add the "Update Docs" agentic workflow

- **Commit:** 20fcef6eb3ed5a8acff5c75fde1937da6a727bad by Jack Ray, 2026-11-13

## Summary
This commit adds a new GitHub Actions agentic workflow, "Update Docs," that keeps repository documentation synchronized with code changes. It is triggered on every push to `main` and can also be run manually. The workflow analyzes diffs, identifies changed entities, and opens a draft pull request with documentation updates. The commit also adds a `.gitattributes` entry so the workflow's compiled lock file is treated as generated code by GitHub (for example, excluded from linguist language stats and collapsed in diffs).

## Reference

### `.gitattributes`
Purpose: Tells Git/GitHub how to treat specific generated files.
Setting added:
```
.github/workflows/*.lock.yml linguist-generated=true
```
Effect: Any `*.lock.yml` file under `.github/workflows/` is flagged as generated content, so GitHub's linguist tool excludes it from language statistics and collapses it by default in diffs.

### `.github/workflows/update-docs.md` — workflow configuration
Purpose: Defines an agentic documentation workflow named "Update Docs" using the `githubnext/agentics` workflow format. It is the human-edited source; running `gh aw compile` regenerates `update-docs.lock.yml` from it.

Key frontmatter settings:

| Option | Value | Meaning |
|---|---|---|
| `on.push.branches` | `[main]` | Runs on every push to `main` |
| `on.workflow_dispatch` | (enabled) | Allows manual runs from the Actions UI |
| `permissions` | `read-all` | Grants the job read-only repository access |
| `network` | `defaults` | Restricts outbound network access to the default allowlist |
| `safe-outputs.create-pull-request.draft` | `true` | Any pull request it opens is created as a draft |
| `safe-outputs.create-pull-request.protected-files` | `fallback-to-issue` | If a change would touch a protected file, it files an issue instead of a PR |
| `safe-outputs.create-pull-request.labels` | `[automation, documentation]` | Labels applied to the created PR |
| `tools.github.toolsets` | `[all]` | Enables all GitHub MCP toolsets |
| `tools.bash` | `true` | Allows unrestricted bash commands within the GitHub Actions VM |
| `timeout-minutes` | `15` | Job timeout |
| `source` / `source-sha` | `githubnext/agentics/workflows/update-docs.md@139fa09ef17cde4135e696ff8e7af09bc5ddfa6e` | Upstream template this workflow was generated from |

Prompt body (role: "Update Docs", an autonomous technical writer):
- **Mission:** ensure every code-level change is mirrored by clear, accurate, stylistically consistent documentation.
- **Voice & tone:** precise, concise, active voice, plain English, progressive disclosure.
- **Workflow steps:**
  1. Analyze repository changes (diff on each push to the default branch) to find new/changed APIs, functions, classes, config, or other significant changes; treat documentation gaps like a failing test.
  2. Assess existing documentation structure and quality against the Diátaxis framework, Google Developer Style Guide, inclusive naming, and the Microsoft Writing Style Guide.
  3. Create or update documentation in Markdown (MDX only when interactive components are indispensable), following progressive disclosure.
  4. Organize content by Diátaxis category (tutorials, how-to guides, technical reference, explanation) with consistent navigation.
  5. Perform quality checks: broken links, missing images, formatting, working code examples, accessibility.
  6. Perform continuous improvement: nightly drift sweeps, incorporate feedback from issues/discussions, maintain the doc toolchain.
- **Output requirement:** create focused draft pull requests when documentation needs updates.
- **Error handling:** suggest a documentation structure if none exists; recommend tooling if build tools are missing.
- **Exit conditions:** exit if the repository has no implementation code, if no changes require documentation updates, or if documentation is already complete.
- **Hard rule:** never push directly to the default branch — always open a pull request for documentation changes.

Usage example (manifest excerpt):
```yaml
on:
  push:
    branches: [main]
  workflow_dispatch:

permissions: read-all
network: defaults

safe-outputs:
  create-pull-request:
    draft: true
    protected-files: fallback-to-issue
    labels: [automation, documentation]

tools:
  github:
    toolsets: [all]
  bash: true

timeout-minutes: 15
```

### `.github/workflows/update-docs.lock.yml` — compiled workflow
Purpose: The generated GitHub Actions workflow file that GitHub Actions actually executes. It is produced mechanically from `update-docs.md` by the `gh aw compile` command and should not be hand-edited; regenerate it whenever `update-docs.md` changes. Its content is an expanded, 2,359-line Actions YAML pipeline (job steps, environment setup, and the agent runner invocation) implementing the configuration above.

## How to use / run
- **Automatic:** push a commit to `main`. The compiled `update-docs.lock.yml` workflow runs in GitHub Actions, inspects the push's diff, and — if documentation needs updating — opens a draft pull request labeled `automation` and `documentation`.
- **Manual:** trigger the workflow from the repository's Actions tab using the `workflow_dispatch` event on `update-docs.lock.yml`.
- **Editing the workflow:** change `.github/workflows/update-docs.md` (the source), then run `gh aw compile` to regenerate `.github/workflows/update-docs.lock.yml`. Do not edit the `.lock.yml` file directly.
