# Add the "Update Docs" agentic GitHub Actions workflow

- **Commit:** 20fcef6eb3ed5a8acff5c75fde1937da6a727bad by Jack Ray, 2026-11-13

## Summary

This commit introduces an automated documentation workflow for the repository. It adds the GitHub Actions workflow source file `update-docs.md` (an "agentic workflow" powered by the `githubnext/agentics` framework), its compiled executable counterpart `update-docs.lock.yml`, and a `.gitattributes` entry that marks compiled `*.lock.yml` workflow files as generated so they are collapsed in GitHub's diff views. Together these changes set up a bot named "Update Docs" that watches pushes to `main`, analyzes the resulting diff, and opens a draft pull request with documentation updates.

## Reference

### `.gitattributes`

Purpose: tells Git/Linguist to treat generated workflow lock files as generated code, so they are hidden by default in diffs and don't count toward language statistics.

```
.github/workflows/*.lock.yml linguist-generated=true
```

### `.github/workflows/update-docs.md` — workflow frontmatter

Purpose: declarative configuration for the agentic workflow, consumed by the `gh aw` compiler to produce `update-docs.lock.yml`.

Key settings:

| Setting | Value | Meaning |
|---|---|---|
| `on.push.branches` | `[main]` | Runs on every push to `main` |
| `on.workflow_dispatch` | (enabled) | Can also be triggered manually |
| `permissions` | `read-all` | Workflow token has read-only access |
| `network` | `defaults` | Uses the default network allowlist |
| `safe-outputs.create-pull-request.draft` | `true` | Any PR it opens is created as a draft |
| `safe-outputs.create-pull-request.protected-files` | `fallback-to-issue` | Falls back to filing an issue if it would need to touch a protected file |
| `safe-outputs.create-pull-request.labels` | `[automation, documentation]` | Labels applied to PRs it creates |
| `tools.github.toolsets` | `[all]` | Full GitHub MCP toolset available |
| `tools.bash` | `true` | Bash is allowed (unrestricted, within the GitHub Actions VM sandbox) |
| `timeout-minutes` | `15` | Job is killed after 15 minutes |
| `source` / `source-sha` | `githubnext/agentics/workflows/update-docs.md@139fa09...` | Upstream template this workflow was generated from |

A commented-out `engine.model: small` block suggests optionally running on a cheaper/smaller model since the workflow fires on every push.

### `.github/workflows/update-docs.md` — job description

Purpose: natural-language instructions given to the AI agent that runs inside the workflow.

Defines an agent persona, "Update Docs" — an **Autonomous Technical Writer & Documentation Steward** — with the following responsibilities:

1. **Analyze Repository Changes** — inspect the diff on each push to the default branch for new/changed APIs, functions, classes, config files; treat documentation gaps as a "red build".
2. **Documentation Assessment** — review existing `docs/`-style directories against the Diátaxis framework, Google Developer Style Guide, inclusive naming, and Microsoft Writing Style Guide.
3. **Create or Update Documentation** — prefer plain Markdown, fall back to MDX only for interactive content, use progressive disclosure (overview first, details second).
4. **Documentation Structure & Organization** — organize by Diátaxis categories (tutorials, how-to guides, technical reference, explanation).
5. **Quality Assurance** — check for broken links, missing images, formatting issues, and verify code examples.
6. **Continuous Improvement** — perform periodic sweeps for documentation drift and incorporate feedback from issues/discussions.

Output requirement: always deliver changes as a **draft pull request**, never a direct push to the default branch. Exit conditions: skip the run if the repo has no code yet, no changes need documenting, or docs are already complete.

### `.github/workflows/update-docs.lock.yml`

Purpose: the compiled, runnable GitHub Actions workflow (YAML) corresponding to `update-docs.md`. It is machine-generated by the `gh aw compile` command and should not be hand-edited; any change to `update-docs.md` requires re-running `gh aw compile` to regenerate this file. Its size (2,359 lines) reflects the boilerplate needed to wire up the agent runtime, MCP tool servers, and safe-output handling described in the source frontmatter.

## How to use / run

- The workflow runs automatically on every push to `main`, or it can be triggered manually from the Actions tab (or `gh workflow run update-docs.lock.yml`) via `workflow_dispatch`.
- To change its behavior, edit `.github/workflows/update-docs.md` (frontmatter and/or job description), then regenerate the compiled workflow with `gh aw compile` before committing — do not edit `update-docs.lock.yml` directly.
- When the agent finds documentation that needs updating, it opens a **draft** pull request labeled `automation` and `documentation` rather than pushing directly to `main`.
